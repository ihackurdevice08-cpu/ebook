01

문제 선정

  • 일상생활과 바로 이어져 직관적으로 이해되는 문제이고, 데이터 분석으로 해결하는 과정이 잘 드러나기 때문에 문제집 5개 중 ‘풀필먼트센터 인력 수요 예측과 배치 최적화’ 문제를 골랐습니다.
02

방법 결정

  • 데이터 설명과 10행 샘플을 보고 가능한 분석 방법을 비교한 뒤, 사용할 방법을 직접 골랐습니다.
  • 시계열 데이터의 누수를 막으려고, 당일 결과 변수는 예측 변수로 쓰지 않았습니다.
  • 바로 실행할 수 있도록, 선택한 방법 전체를 파이썬 파일 하나로 구성했습니다.
03

분석 실행·보완

  • 결과를 직접 확인하려고, 코드를 Antigravity에서 실행했습니다.
  • 결론에서 약한 재배치 효과와 검증 기간 편중을 보강하려고, 요일·날씨별 출고율, 미처리 물량과 잔업, 센터 간 재배치, 검증 구간 2개, 보정 계수 탐색을 추가했습니다.
04

보고서 작성·수정

  • 앞에서 뒤까지 이어서 읽으면 이해되도록, 문제, 원인, 해결, 효과, 비용, 운영, 결론 순서의 개조식으로 구성하고 장마다 말하려는 내용을 하나로 좁혔습니다.
  • 처음 보는 사람도 이해하도록, SLA와 UPH 같은 약어를 출고율과 시간당 처리량으로 풀어 썼습니다.
  • 결론이 과장되어 보이지 않도록, 한계는 짧게 쓰고 센터 간 이동은 "일부 센터만 부족한 날의 보조 수단"으로 바꿨습니다.
  • 문장이 자연스럽게 읽히도록, 단어와 호응은 직접 읽으며 고쳤습니다.
  • 보고서를 읽지 않은 사람도 같은 결론을 이해하도록, 같은 메시지로 영상도 만들었습니다. (영상 기획 의도 참고)
05

교차 검증·반영

  • 한 AI의 오류를 놓치지 않도록, 분석 결과와 코드를 다른 AI(GPT)로도 확인했습니다. 코드를 다시 실행해 핵심 수치를 새로 계산하고 보고서와 대조했습니다.
  • 지적받은 내용이 맞는지 가리려고, 원본 데이터로 직접 다시 계산했습니다.
  • 숫자 오류는 없었고 단위와 범위 표현만 고쳤습니다. 수정 전후는 검증과 수정에 있습니다.
직접 만든 스킬

직접 제작한 스킬들을 활용했습니다.

스킬어떤 의도로 구성한 스킬인지이 과제에서 어떻게 썼는지
한글 작성 기준문장을 틀에 끼우지 않고 전달할 뜻을 먼저 정한 뒤, 조사와 단어 호응에 맞게 쓰도록 만들었습니다. 문장 기준과 직접 고친 교정 사례를 함께 담았습니다.보고서 문장의 단어와 호응을 고칠 때 기준으로 삼았습니다. "짜였을까요"를 "구성되었을까요"로 바꾸고 SLA와 UPH를 출고율과 시간당 처리량으로 풀어 썼으며, 사이트 문구도 같은 기준으로 고쳤습니다.
문서 작성 절차쓰기 전에 목적과 분량을 정하고, 전체 메시지와 장별 메시지를 먼저 확정한 뒤 위계와 강조 단계를 지켜 쓰도록 만들었습니다. 검증과 전달 순서까지 한 절차로 묶었습니다.보고서를 문제, 원인, 해결, 효과, 비용, 운영, 결론 순서로 구성하고 제목과 강조의 위계를 맞췄습니다. 영상 구성에도 같은 방식을 적용했습니다.
글쓰기 기준목적과 읽는 사람을 먼저 정하고, 다듬기 전에 사실을 검증하며, 구성이 바뀌는 결정은 확인받고 진행하도록 만들었습니다.다른 AI로 핵심 수치를 다시 계산해 단위 표현 7곳을 고쳤습니다. 구성이나 분량이 바뀌는 수정은 먼저 확인한 뒤 반영했습니다.
디자인 방향 설정용도를 먼저 판단해 색, 위계, 여백의 기준을 정하고, 완성된 화면을 직접 확인하도록 만들었습니다. 학교 과제는 흰 배경에 어두운 파랑 한 가지만 쓰는 기준입니다.흰 배경에 네이비 한 가지 포인트색, 위계와 여백 기준을 사이트에 적용했습니다. 영상에서는 작업자 옷, 표, 아이콘의 색을 줄이는 기준으로 썼습니다.
업무 보고서 제작요약을 앞에 두고 본문과 참고문헌으로 이어지는 보고서 틀과, 핵심 결론 박스와 표, 차트, 쪽 레이아웃의 기준을 담았습니다.결론이 먼저 보이는 구성 틀을 보고서의 장 구성에 참고했습니다.
사용한 프롬프트

분석 방법 결정

쓸 수 있는 방법을 비교해 직접 고를 수 있도록 프롬프트를 구성했습니다.

  • 데이터 설명 파일과 10행 샘플을 주고, 가능한 분석 방법과 사용 변수, 알 수 있는 내용을 받는 형태로 썼습니다.
  • 시계열 누수를 막기 위해 당일 결과 변수는 예측에 쓰지 않는 조건을 넣었습니다.

분석 코드 생성

고른 방법을 바로 실행해 결과를 확인할 수 있도록 프롬프트를 구성했습니다.

  • 방법 전체가 파이썬 파일 하나로 실행되는 형태로 썼습니다.
  • 결과표, 그림, 요약은 정해진 폴더에 저장되는 조건을 넣었습니다.

보고서 생성

처음 보는 사람도 앞에서 뒤까지 막힘없이 이해할 수 있도록 구성, 문체, 용어, 수치의 기준을 프롬프트에 넣었습니다.

  • 구성: 문제, 원인, 해결안, 효과, 비용, 운영, 결론 순서이고 장마다 말하려는 내용은 하나만 둡니다.
  • 문체: 개조식이고 한 문장에는 판단 하나만 둡니다.
  • 용어: SLA, UPH 같은 약어는 출고율, 시간당 처리량처럼 쉬운 말로 풉니다.
  • 수치: 분석 결과 파일의 값만 쓰고, 직접 계산한 값은 자체 계산으로 표기합니다.
  • 다듬기: 한 번에 끝내지 않고 읽는 사람 기준으로 반복해 고쳤습니다. 약어를 풀어 쓰고, 센터 간 이동은 보조 수단으로 표현하고, 문장 호응은 직접 읽으며 맞췄습니다.

영상 제작

보고서를 읽지 않은 사람도 문제와 해결을 이해할 수 있도록 영상의 형식과 제작 순서를 프롬프트에 넣었습니다.

  • 형식: 얼굴 없는 2D 설명 영상이고, 나레이션 없이 자막과 직접 만든 음악만 씁니다.
  • 순서: 전체 메시지, 장면별 메시지, 자막, 화면 수치를 먼저 확정한 뒤에 제작합니다.
  • 자막: 보고서 문장을 그대로 옮기지 않고 설명 영상 대본처럼 이야기 흐름에 맞춥니다.
  • 화면: 택배 박스 장면과 숫자·그래프를 한 화면에 함께 두고 불필요한 글자 효과는 쓰지 않습니다.
  • 다듬기: 완성된 화면과 자막을 처음부터 끝까지 보며 반복해 고쳤습니다. 컨베이어 장면은 중앙으로 맞추고, 색은 줄이고, 로고와 장 제목 위치는 읽기 편하게 조정했습니다.

교차 검증

한 AI의 오류를 놓치지 않도록 다른 AI(GPT)로도 확인하는 프롬프트를 구성했습니다.

  • 코드를 다시 실행해 핵심 수치를 새로 계산하고 보고서와 대조하는 형태로 썼습니다.
  • 확인된 오류와 의견을 구분해 표로 받는 조건을 넣었습니다.
